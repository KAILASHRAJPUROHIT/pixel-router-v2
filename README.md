# pixel-router

Turning a used Pixel 6 into a permanent, always-on 5G/4G hotspot router, plus tooling to monitor, control, and display its status.

## Structure

- **`aod/`** — Android app implementing a custom always-on display (Daydream/DreamService) that mirrors the router's live status natively on the phone's lock screen: connection speed, connected devices, data usage, battery, thermal state, SMS-forwarder health, internet reachability, signal quality, a combined health traffic-light, AKD social follower counts, Hindu Panchang, and weather. **30 selectable layouts** (structural styles - corner stack, centered radial, split halves + grid, sidebar rail, ticker marquee, widget cascade, giant stack, mega grid, bento modern, glyph minimal, plus 10 phone-OEM-style variants and 10 vibrant multi-color variants) and **9 color themes** (neon cyberpunk, glass frost, retro CRT terminal, luxury gold, vaporwave sunset, e-ink newspaper, holographic, nature organic, true black/OLED), picked via `AodSettingsActivity` or directly from the web dashboard. Every layout shows the complete stat set - layouts vary presentation, not what data is included. Includes automatic safety cutoffs (pauses itself above 45°C or below 30% battery), adaptive day/night brightness, OLED burn-in protection (periodic pixel-shift), and a self-rendered preview PNG the dashboard displays live.
- **`router-scripts/`** — everything running on the phone itself: `update.sh` (the dashboard generator loop), `service.d/` (boot-time watchdogs and monitors), `cgi-bin/` (the dashboard's interactive endpoints), and `lib/` (shared shell helpers). See that directory's own README for the full breakdown.
- **`ai/`** — Local Ollama-based monitoring layer that polls the router's dashboard, keeps a rolling history, flags anomalies, answers natural-language questions about router health, and posts desktop alerts. Also includes `heartbeat.py` (fast 60s reachability check, decoupled from the heavier analysis loop, with its own up/down desktop alerting) and `uptime_summary.py` (prints an outage/uptime report from the heartbeat log). Runs independently of the phone — the router itself stays a dumb, deterministic device with no AI dependency of its own. Both `analyzer.py` and `heartbeat.py` run persistently via Windows Scheduled Tasks, launched with `pythonw.exe` (no console window) with their output redirected to `data/*_console.log`.
- **`router-scripts/ec2-vpn-server/`** — reference/backup for what's running on an AWS EC2 t3.micro (`ap-south-1`, fixed Elastic IP): a WireGuard server the phone tunnels to, and Caddy reverse-proxying the dashboard to a permanent HTTPS URL (with fail2ban watching for basic-auth brute force). See that directory's own README.

## Key subsystems

- **Web dashboard** — served locally by busybox httpd on the phone (`:8080`), exposed publicly two ways: through the WireGuard tunnel + Caddy on the EC2 box (fail2ban-protected), and via a Cloudflare quick tunnel (`cloudflared_tunnel.sh`, **not** fail2ban-protected - same basic-auth password is the only gate on that path). Card-based layout: network/device-health/AKD stats, custom-message-to-AOD, AOD layout/theme/billing-day controls + live preview, connected-device table (rename/deny per device), recent SMS grouped by sender, and a debug/admin panel (service restarts, reboot, and a root shell console).
- **Multi-tier internet failover** (`failover_monitor.sh`) — when the phone's own cellular goes down or hits a configurable 300GB/cycle cutoff (`cellular_quota_monitor.sh`), it borrows a family member's iPhone Personal Hotspot: detects presence via Bluetooth (unreliable for iPhones due to address randomization, kept as a secondary signal) or Wi-Fi, sends an SMS that triggers a Shortcuts Personal Automation on that iPhone (checks its own location, turns on Personal Hotspot only if home), connects, and auto-reverts once the phone's own cellular recovers.
- **Airtel tethering-detection bypass** (`vpn_tether_routing.sh`) — while genuinely using cellular data as the uplink (not borrowed Wi-Fi), routes tethered hotspot-client traffic through the WireGuard tunnel instead of raw cellular, since Airtel can detect/throttle unmasked tethered traffic. This is now a **persistent watchdog**, not a one-shot boot script - it continuously re-checks both `internet_type` (only bypasses when on own cellular, never when borrowing Wi-Fi - no carrier-detection concern there) and whether the tunnel is actually alive (tracks `rx_bytes` deltas; a present-but-unresponsive tunnel is treated as down, not routed into). A dead-but-present tunnel silently black-holing hotspot traffic was a real incident (2026-07-06/07) that this rewrite fixes.
- **SMS relay + forwarding** — incoming SMS mirrored to the dashboard (grouped by sender), while a third-party app (`cn.ppps.forwarder`) forwards real messages to the owner's phone via a SQLite rule with a negative-lookahead regex blacklist for known noise senders (Jio quota alerts, weather warnings, etc.).
- **Remote debugging** — `adb` over Wi-Fi/the WireGuard tunnel, firewalled to a specific laptop MAC + `tun0` + loopback only (not open to the whole hotspot network), plus the dashboard's own root-shell console (audit-logged).

## Setup

Real credentials/secrets are **not** committed to this repo - copy each `.example` file and fill in your own values:

- `aod/dashboard.properties` (from `.example`) — router dashboard basic-auth credentials.
- `ai/local_secrets.py` (from `.example`) — same credentials, for the AI monitoring layer.
- `router-scripts/failover.properties.example` — family members' phone numbers, hotspot SSID/password/MAC/Bluetooth MAC for the failover system.
- `router-scripts/akd_secrets.properties.example` — API URL/key for the AKD follower-count integration.

See each subproject's own README for further details on running/building/deploying.
