# router-scripts

Backup/reference copies of the shell scripts and CGI endpoints actually running on the router phone itself (rooted Pixel 6, via Magisk `service.d` + a busybox `httpd`). These are **not deployed automatically from this repo** — they're pushed to the device manually via `adb push` + `adb shell su -c 'cp ...'`, same as they were originally installed. This directory exists purely so the on-device automation has version control and isn't only living as a single copy on the phone's storage.

- **`service.d/`** — mirrors `/data/adb/service.d/` on the phone. Long-running watchdogs/monitors (registered in `service_supervisor.sh`'s `SCRIPTS` list, which restarts any of them that dies): hotspot uptime (`hotspot_watchdog.sh`), AOD state (`aod_watchdog.sh`, `aod_status_poller.sh`, `aod_power_governor.sh`, `aod_preview_sync.sh`), dashboard uptime (`dashboard_watchdog.sh`), internet failover (`failover_monitor.sh`), Airtel tethering-detection bypass (`vpn_tether_routing.sh`), cellular data cutoff (`cellular_quota_monitor.sh`), thermal/connection/QoS tuning, SMS-forwarder health, new-device detection, log rotation, and AKD follower-count polling. Plus one-shot boot scripts (not in the supervisor list, meant to run once and exit): hotspot bring-up, battery charge limit, conntrack tuning, dashboard bring-up, permanent underclock, MAC-blocklist re-application, remote-adb re-enablement.
- **`cgi-bin/`** — the dashboard's interactive POST endpoints: custom AOD message, AOD layout/theme picker, billing-cycle-day picker, device rename/deny, and the admin debug panel (service restarts/reboot + a root shell console, audit-logged to `debug_console.log`).
- **`lib/`** — shared shell helpers sourced by multiple scripts, instead of copy-pasted (`net_common.sh`: WAN-interface detection and byte counting, used by `update.sh`, `speed_monitor.sh`, and `cellular_quota_monitor.sh` - deployed to `/data/adb/dashboard/lib_net_common.sh`).
- **`update.sh`** — mirrors `/data/adb/dashboard/update.sh`, the dashboard HTML generator loop (regenerates `index.html` every cycle; `speed_monitor.sh` writes a separate fast-polling `speed.json` the page's own JS reads independently).
- **`ec2-vpn-server/`** — see its own README for the AWS-side WireGuard/Caddy/fail2ban setup this all depends on for remote access.
- **`*.properties.example`** — templates for the real config files (`failover.properties`, `akd_secrets.properties`, `meta_secrets.properties`), which contain real phone numbers/passwords/API keys and are gitignored. `config_validate.sh` checks these against the real files on every boot.
- **`meta_secrets.properties.example`** — optional. If present on-device, `akd_followers_fetch.sh` fetches Instagram/Facebook numbers directly from the Meta Graph API instead of via AKD's own relay, so a stale/expired token on AKD's side stops being a single point of failure for what this router's dashboard shows. YouTube stays sourced from AKD either way.

**Redacted for this repo**: a couple of hardcoded *fallback* SSID/password values (rarely-hit last-resort defaults used only if the real WifiConfigStoreSoftAp.xml config is unreadable, in `hotspot_on_boot.sh`/`connection_optimizer.sh`) are replaced with `CHANGEME_SSID`/`CHANGEME_PASSWORD` placeholders here. The actual on-device copies have the real values — this is just about not committing them in plaintext to git.
