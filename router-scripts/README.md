# router-scripts

Backup/reference copies of the shell scripts and CGI endpoints actually running on the router phone itself (rooted Pixel 6, via Magisk `service.d` + a busybox `httpd`). These are **not deployed automatically from this repo** — they're pushed to the device manually via `adb push` + `adb shell su -c 'cp ...'`, same as they were originally installed. This directory exists purely so the on-device automation has version control and isn't only living as a single copy on the phone's storage.

- **`service.d/`** — mirrors `/data/adb/service.d/` on the phone. Long-running watchdogs/monitors (registered in `service_supervisor.sh`'s `SCRIPTS` list, which restarts any of them that dies): hotspot uptime (`hotspot_watchdog.sh`), AOD state (`aod_watchdog.sh`, `aod_dream_recovery.sh`, `aod_power_governor.sh`, `aod_preview_sync.sh`), dashboard uptime (`dashboard_watchdog.sh`), internet failover (`failover_monitor.sh`), Airtel tethering-detection bypass (`vpn_tether_routing.sh`), cellular data cutoff (`cellular_quota_monitor.sh`), thermal/connection/QoS tuning, SMS-forwarder health, new-device detection, log rotation, AKD follower-count polling, and a coordinating supervisor (`hotspot_manager.sh` - watches for cross-cutting failures no single narrow watchdog can see alone: a script restart-looping without actually recovering, a borrowed hotspot connection with no real internet behind it, sustained poor signal as an early warning before failover triggers, and hotspot+dashboard+AOD all down at once, which escalates to a full reboot as a last resort). Plus one-shot boot scripts (not in the supervisor list, meant to run once and exit): hotspot bring-up, battery charge limit, conntrack tuning, dashboard bring-up, permanent underclock, MAC-blocklist re-application, remote-adb re-enablement.
- **`aod_dream_recovery.sh`** — a fast, lightweight companion to `aod_watchdog.sh`'s slower 120s loop, with its own heat/network budget (adaptive interval, 5s-60s, same doubling-backoff shape as `hotspot_manager.sh`). Android's own SystemUI periodically attempts to switch the active dream to its stock charging-clock dream regardless of that component already being disabled, tearing down the router's own dream in the process before the switch itself fails - `aod_watchdog.sh`'s heavier fix (force-stop + toggle + wake) is both too slow and too heavy to keep up with that; this just runs `cmd dreams start-dreaming` the moment it notices, which is fast enough that the disruption stays imperceptible instead of visibly flickering the display every ~10-15s. Also absorbed `aod_status_poller.sh`'s job (retired 2026-07-08) - that script polled the identical dumpsys calls every single second forever with a heavier, fully redundant fix action; two watchdogs independently hammering the same syscalls on different clocks was waste, not extra safety.
- **`cgi-bin/`** — the dashboard's interactive POST endpoints: custom AOD message, AOD layout/theme picker, billing-cycle-day picker, device rename/deny, an on-demand speed test (`speedtest.cgi` - runs on the router itself against Cloudflare's public test endpoints, not in the viewer's browser, since the dashboard is often viewed remotely through a tunnel where a browser-side test would measure the wrong path), a chat window into `hotspot_manager.sh`'s own state (`manager_chat.cgi` - keyword-matched against real status/log files, explicitly not a language model), a PC restart/RustDesk restart command queue, and the admin debug panel (service restarts/reboot + a root shell console, audit-logged to `debug_console.log`).
- **`lib/`** — shared shell helpers sourced by multiple scripts, instead of copy-pasted (`net_common.sh`: WAN-interface detection and byte counting, used by `update.sh`, `speed_monitor.sh`, and `cellular_quota_monitor.sh` - deployed to `/data/adb/dashboard/lib_net_common.sh`).
- **`update.sh`** — mirrors `/data/adb/dashboard/update.sh`, the dashboard HTML generator loop (regenerates `index.html` every cycle; `speed_monitor.sh` writes a separate fast-polling `speed.json` the page's own JS reads independently).
- **`ec2-vpn-server/`** — see its own README for the AWS-side WireGuard/Caddy/fail2ban setup this all depends on for remote access.
- **`*.properties.example`** — templates for the real config files (`failover.properties`, `akd_secrets.properties`, `hotspot_secrets.properties`, `meta_secrets.properties`), which contain real phone numbers/passwords/API keys and are gitignored. `config_validate.sh` checks these against the real files on every boot.
- **`hotspot_secrets.properties.example`** — the hotspot's own SSID/password, read by `hotspot_on_boot.sh`/`hotspot_health_check.sh`/`connection_optimizer.sh` (the last one now just delegates to `hotspot_on_boot.sh` instead of keeping its own copy of this logic). Replaced an older approach (reading dynamically from Android's own SoftAp config, with a redacted-placeholder fallback) after that caused a real full lockout live 2026-07-08 - the dynamic read had silently stopped working after an OS update, and the fallback ended up broadcasting the literal placeholder string as the actual password. A gitignored properties file can't fail that particular way: it either has the real value or is missing entirely, which fails loudly instead of silently.
- **`hotspot_health_check.sh`** — catches the two failure modes that combined into that lockout: the hotspot password reverting to a placeholder, and the laptop/TV (locked to 5GHz-only via a MAC deny-list on 2.4GHz, see `hotspot_on_boot.sh`) having nowhere to connect if the 5GHz radio isn't actually up. Checks every 60s, not just at boot, since a restart from any source (the dashboard's own button, `hotspot_watchdog.sh`, a person on adb) can retrigger either one.
- **`meta_secrets.properties.example`** — optional. If present on-device, `akd_followers_fetch.sh` fetches Instagram/Facebook numbers directly from the Meta Graph API instead of via AKD's own relay, so a stale/expired token on AKD's side stops being a single point of failure for what this router's dashboard shows. YouTube stays sourced from AKD either way.
